# WHERE THE INSTALLER GETS WHAT THIS COMPUTER DOESN'T HAVE
#
# Every address here says where it came from, how it's checked, and
# what we pay for it.
#
# WHY THIS IS PLAIN TEXT AND NOT CODE. The Python address is needed by
# two readers: the shell script that downloads Python, and Python, which
# downloads everything else. The shell can't read Python code, Python
# doesn't read shell scripts — and a number written in two places will
# one day drift apart, quietly. So there's one list and two readers, in
# a format that awk, Python and a person can all read.
#
# Rows: words separated by spaces. Empty lines and lines starting with
# # are skipped.
#
# EVERYTHING THAT GETS DOWNLOADED IS CHECKED. Programs arrive here that
# will be run, and "downloaded and ran it" without checking means taking
# someone else's server at its word. The checksums were taken by hand on
# 3 September 2026: downloaded, unpacked, computed. The Mac ones match
# the ones published on the builder's website.
#
# IF A CHECKSUM DOESN'T MATCH, THE INSTALL STOPS AND SAYS SO IN WORDS.
# Not "probably an update": an update can't be told apart from
# tampering, and that's for a person to decide, not the program.

# ── FFMPEG ────────────────────────────────────────────────────────────
#
# FIRST WE LOOK WHETHER IT'S ALREADY ON THE COMPUTER, and only then
# download it. People with Homebrew usually have it, and a second copy
# would mean 45 MB for nothing plus the question "which of the two is
# being used".
#
# VERSIONS. Vertcut was measured on ffmpeg 8.1.2; the downloads are 9.0
# (macOS Apple Silicon), 8.0 (macOS Intel) and 9.0.1 (Windows). For 9.0
# this was CHECKED, not hoped for: the whole path — analysis, picking
# a segment, export — was run on the downloaded 9.0 build, with the same
# clip length and the same check results as on 8.1.2. The Windows 9.0.1
# build is run by the build machine: Vertcut's tests run on it. The Intel
# 8.0 build HAS NEVER BEEN RUN ANYWHERE — only its checksum was checked.
# This matters: ffmpeg has changed how seeking behaves between versions
# before, and that once cost a lot of work.
#
# LICENSE. These builds are under the GPL: they include the x264
# encoder, which is GPL. WE DO NOT DISTRIBUTE FFMPEG — your computer
# downloads it from the website of whoever built it. Vertcut calls ffmpeg
# as a separate program, so its GPL wouldn't apply to our code even if we
# put ffmpeg in the archive. Distributing it would oblige us to something
# else: shipping the license text and the SOURCE CODE of exactly that
# build — for every system and every update. By not distributing it we
# don't carry that, the archive stays small, and anyone who already has
# ffmpeg doesn't get a second copy. The license text is put next to the
# program file.
#
# WHAT WE PAY. The Mac builds keep the same file name when they're
# updated, so after an update the checksum won't match. That's not a
# breakage but a conversation: Vertcut will say that the file at that
# address has changed and suggest either getting a newer Vertcut or
# installing ffmpeg yourself.
#
# The Windows build has its version number in the file name, and the
# release is tagged with it too. Its archive holds both programs and the
# license text.
#
# THE ADDRESS HAS DIED HERE BEFORE, AND THAT'S WHY IT'S DIFFERENT NOW.
# It used to point at a "nightly" build, and the builder deletes those as
# new ones come out: on 20 September 2026 it returned 404, meaning the
# Windows install didn't work for anyone at all. The build machine found
# it — the first thing to actually install Vertcut on a real Windows.
#
# Now it's a build with a PERMANENT release tag — a version number, not
# a date. Those releases aren't deleted, and both addresses — Mac and
# Windows — are of the same kind now: a version, not "latest".
#
# The Mac checksums are of the PROGRAM FILES inside the archive, not of
# the archive: those are what the builder publishes, and those are what
# actually runs.
